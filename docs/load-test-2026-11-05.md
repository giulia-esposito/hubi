# Load and soak test, 2026-11-05 (audit item P1-10)

**Tool:** `scripts/load-test.ts`. **Target:** a local production build (`next start`, commit `7488083`) on a Windows laptop, real Gemini 2.5 Flash on Vertex in `wh-revenue-sandbox`, the real corpus. Single-turn questions in a mix of English and Portuguese, one simulated user per concurrent slot. The deployed service is internal-only behind IAP and was not called.

409 requests, 0 failures, no 429 from Vertex, no `busy` or `circuit-open` refusals.

## What it shows

1. **One instance serves about 60 to 70 turns per minute, whatever the concurrency.** Throughput is flat from 10 to 50 concurrent users while latency grows: requests queue behind the per-instance cap of 16 concurrent model calls (`maxConcurrent`, `lib/runtime/resilience.ts`). A turn uses 2 to 3 model calls (scope judge, optional query expansion, the answer). The queue wait limit is 15 s, and no request exceeded it.
2. **Up to about 10 simultaneous users on one instance the experience is good** (median 7 s to the full answer, text starts in about 6 s). At 25 it is acceptable (10 s median). At 50 on one instance the median becomes 21 s: Cloud Run would normally scale out well before that (`maxScale` is 20).
3. **Memory is not a constraint.** The server's working set was 245 MB after the busy runs and 160 MB after the soak, against a 2 Gi limit: no growth over 409 requests.
4. **Vertex quota was not reached** at about 200 model calls per minute.
5. **Tail latency is the model's, not the app's.** The soak at concurrency 10 had a p95 of 36 s while the earlier run at the same concurrency had 18 s: the long tail comes from occasional slow Gemini responses (thinking tokens), which the 60 s call timeout bounds.

## Cost per turn

The server's usage report did not survive the stop, so this is an estimate from the measured per-scenario usage of the live evals (about 6.6k input and 2.5k output and thinking tokens per single-turn question), at assumed list prices of $0.30 and $2.50 per million tokens: about **$0.008 per turn**, so roughly **$3** for the 409 requests (range $2 to $4). Cloud Billing is authoritative. A pilot of 50 users asking 20 questions a day would be about $8 a day.

## Decisions and recommendations

- **`maxScale`:** leave at 20. It is not the limiting factor.
- **Per-instance concurrency:** the service default (80 concurrent requests per instance) is higher than the 16-call model cap, so a burst queues inside one instance before Cloud Run scales out. For a larger rollout, ask Platform to set Cloud Run concurrency to about 10 to 16 so scale-out starts when queues would form. It is service config (sandbox-managed), so it is not changed here. Not needed for the pilot.
- **`HUBI_ENGINE_MAX_CONCURRENT`:** keep 16 until Vertex quota is confirmed with Platform. Raising it trades queueing for a higher 429 risk.
- **Not covered:** the buffered verify-and-revise path (artifact follow-ups, 6 to 9 s more per turn, needs multi-turn requests), cold starts and Cloud Run networking (the target was local), and quota behavior above about 70 turns per minute. Re-run against the deployed service with `--header "Authorization: Bearer <identity token>"` from a machine that can reach it before any wider rollout.
